# Проверка блогеров

По умолчанию выполнять глубокую проверку реальных публичных ссылок. Не заменять её
быстрым режимом или синтетическим демо без явной просьбы пользователя. Не сообщать
«контент проверен», если ролики или речь фактически не открылись.

## Режимы

1. `onegroup-full` — основной режим: вся личная таблица, 10 последних роликов каждого блогера, метрики, мат с таймкодами и цитатами, конкуренты, подробный комментарий и запись в H и N:S.
2. `single-full` — глубокая проверка одного ролика или профиля, когда пользователь не передал таблицу.
3. `quick-live` — только явно запрошенная быстрая диагностика метрик. Он не проверяет речь и не должен использоваться вместо полной проверки подборки.
4. `demo` — только явно запрошенный учебный резерв на синтетических данных.

## Полный сценарий Google Sheets

Перед работой прочитать [references/google-sheets.md](references/google-sheets.md).

1. Если навык установлен впервые, проверить наличие `SKILL.md`, `scripts/bootstrap_deep.py`, `scripts/sheet_run.py`, `scripts/check_roller.py`, `scripts/make_paste.py` и `slovar.json`.
2. Участник создаёт личную копию [учебного шаблона](https://docs.google.com/spreadsheets/d/1DzqwIBC4nvX2VFtv6q2imZGHwpUxgDmg1jDvoAu90_s/copy) и передаёт её ссылку. ID назначения обязан отличаться от ID шаблона.
3. Проверить, что доступ к личной копии установлен как «Все, у кого есть ссылка — читатель». Навык читает только открытые данные; ключи и cookies не нужны.
4. Запустить полный проход:

   ```bash
   python3 scripts/bootstrap_deep.py \
     --sheet-url "ССЫЛКА_НА_ЛИЧНУЮ_КОПИЮ" \
     --videos 10 \
     --output output/onegroup-full
   ```

   Скрипт сам создаёт изолированное окружение в пользовательском кэше и ставит `yt-dlp`, `curl_cffi`, локальный Whisper и ffmpeg. Ничего не ставить глобально. На первом ролике без субтитров скачивается модель распознавания; это самый долгий разовый этап, повторные запуски используют кэш. По умолчанию обрабатывать все строки с публичными ссылками; не добавлять `--max-profiles`, если пользователь не попросил диагностический тест.
5. Дождаться окончания. После каждого блогера промежуточный `результат.json` сохраняется на диск. Не выдавать частичный файл за полностью завершённый проход.
6. Проверить:
   - число строк в `результат.json` равно числу открытых профилей в таблице;
   - у каждой доступной строки запрошено до 10 последних роликов;
   - `sheet-write-plan.json` содержит диапазоны H и N:S для всех обработанных строк;
   - в комментариях с найденным матом есть слово, цитата, таймкод и прямая ссылка на ролик;
   - упоминания конкурентов содержат бренд, место совпадения и ссылку;
   - ролики без доступной расшифровки явно посчитаны, а не объявлены чистыми.
7. Показать пользователю краткую сводку и `sheet-write-plan.json`: название личной копии, вкладку, количество строк и диапазоны. До подтверждения ничего не записывать.
8. После явного подтверждения записать через Google Drive/Sheets-коннектор только H и N:S, сохранив оформление и формулы остальных колонок. Затем перечитать записанные диапазоны и сверить минимум 3–5 строк с планом.
9. Если коннектора нет, использовать резервные `блок_H.tsv` и `блок_N_S.tsv`: первый вставить в H первой строки, второй — в N той же строки. Не просить API-ключ и не имитировать запись.

## Отдельный ролик

Для глубокой проверки конкретного ролика выполнить:

```bash
python3 scripts/check_roller.py "URL_РОЛИКА" \
  --brief assets/onegroup-brief.json \
  --workdir output/single-full
```

Субтитры площадки использовать в приоритете. Если их нет, допускается локальное
распознавание речи при установленном `mlx-whisper`; отсутствие распознавания обязательно
указывать как незакрытую проверку, а не как отсутствие мата.

## Быстрый и деморежимы

Быструю проверку запускать только по прямой просьбе «быстро», «тестово» или «на 1–2
профилях». Её результат обязан содержать пометку, что речь не проверялась:

```bash
python3 scripts/bootstrap_live.py --profile "URL" --limit 3 --output output/quick-live
```

Демо запускать только как явно обозначенный план Б:

```bash
python3 scripts/demo_screening.py --output output/demo-screening
```

## Правила решений

- Не заполнять отсутствующие факты догадками.
- Исключать из среднего просмотры выше трёх медиан и показывать число выбросов.
- Мат подтверждать таймкодом, цитатой и URL ролика.
- Конкурента подтверждать брендом, местом совпадения и URL ролика.
- При закрытом профиле или ошибке площадки ставить «Проверить вручную» и сохранять ошибку.
- Если часть роликов без расшифровки, указывать их число и необходимость ручного просмотра.
- Не считать визуальные логотипы проверенными только по речи или описанию.

## Границы

Навык анализирует открытые профили, субтитры площадки, локально распознанную речь и
описания. Метрики являются снимком на момент запуска. Финальное решение, визуальные
логотипы в кадре, договорные ограничения и редкие ролики, где не удалось скачать ни
расшифровку, ни аудио, остаются на контроле человека.
