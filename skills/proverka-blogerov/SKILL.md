# Проверка блогеров

По умолчанию решать задачу на реальных публичных ссылках пользователя. Не подменять
неудачный интернет-прогон синтетическим демо и не сообщать «проверено», если профиль
или ролики фактически не открылись.

## Режимы

1. `quick-live` — основной практический режим. Проверить 1–2 реальных профиля по трём последним публичным роликам. Сам подготавливает лёгкое изолированное окружение без API-ключей.
2. `full-live` — рабочий повтор quick-live по 10 роликам. Использовать после быстрого прогона; контентные риски по речи и кадрам требуют отдельного глубокого прохода.
3. `public-sheet` — взять ссылки из публичной Google-таблицы. Читать можно без токена; внешнюю запись выполнять только через доступный Google-коннектор и после подтверждения.
4. `demo` — только запасной или явно запрошенный режим на встроенных синтетических данных.

## Рабочий порядок

1. Если пользователь передал профиль или CSV, начать с quick-live. Для Google Sheets сначала прочитать [references/google-sheets.md](references/google-sheets.md).
2. Если передан ZIP/папка навыка впервые, проверить наличие `SKILL.md`, `scripts/bootstrap_live.py` и `assets/live-input-template.csv`.
3. Если пользователь просит практику Onegroup с личной таблицей:
   - при подключённом Google Drive сначала показать намерение, после подтверждения скопировать шаблон целиком, получить фактическую ссылку созданной копии и проверить, что её ID отличается от исходного;
   - без коннектора выполнить `python3 scripts/open_onegroup_template.py`: участник нажимает «Создать копию» и возвращает ссылку новой таблицы;
   - не продолжать запись, пока документ назначения всё ещё является исходным шаблоном.
4. Для CSV с реальными ссылками выполнить:

   ```bash
   python3 scripts/bootstrap_live.py --input profiles.csv --limit 3 --max-profiles 2 --output output/live-screening
   ```

   Скрипт один раз устанавливает `yt-dlp` и `curl_cffi` в отдельный кэш навыка. Не ставить их глобально и не просить у пользователя API-ключ.

   Для одной или двух ссылок CSV не нужен:

   ```bash
   python3 scripts/bootstrap_live.py --profile "URL_1" --profile "URL_2" --limit 3 --output output/live-screening
   ```

5. Для публичной Google-таблицы выполнить:

   ```bash
   python3 scripts/bootstrap_live.py --sheet-url "ССЫЛКА" --limit 3 --max-profiles 2 --output output/live-screening
   ```

   Для практики Onegroup использовать личную копию [учебного шаблона](https://docs.google.com/spreadsheets/d/1DzqwIBC4nvX2VFtv6q2imZGHwpUxgDmg1jDvoAu90_s/copy), вкладку `Несогласованные блогеры`. Навык читает ссылки и стоимость из строк таблицы, а затем готовит точный план заполнения H и N:S. Подробнее — в [references/google-sheets.md](references/google-sheets.md).

6. Проверить четыре файла: `live-results.csv`, `live-results.json`, `live-report.md`, `for-sheet.tsv`. Сообщить дату снимка, число открытых роликов и прямые ссылки-доказательства.
7. Если пользователь хочет продолжить рабочую проверку, повторить с `--limit 10`. Не утверждать, что мат, конкуренты или визуальные риски отсутствуют: quick-live их не проверяет.
8. Для записи в Google Sheets сначала показать `sheet-write-plan.json`, назвать личную копию, вкладку и диапазоны, получить подтверждение, затем записать через доступный Google-коннектор и перечитать H и N:S. Никогда не писать в исходный шаблон. Если коннектора нет — для соседних строк вставить `for-onegroup-H.tsv` в H первой строки и `for-onegroup-N-S.tsv` в N первой строки.
9. Демо запускать только по явной просьбе или как обозначенный план Б:

   ```bash
   python3 scripts/demo_screening.py --output output/demo-screening
   ```

## Правила решений

- Не заполнять отсутствующие факты догадками.
- Quick-live — предварительный числовой скрининг, не проверка речи или изображения.
- Если открылись не все запрошенные ролики, явно показать фактическое число.
- При недоступном или закрытом профиле ставить «Проверить вручную» и сохранять ошибку вместо вымышленных метрик.
- Если прогноз ниже 75% целевого, ставить «С оговоркой».
- В остальных случаях ставить «Предварительно подходит», пока не выполнена контентная проверка.
- Исключать из среднего просмотры выше трёх медиан, но обязательно показывать число исключённых выбросов.

## Границы

Результат — актуальный первичный скрининг открытых данных, а не финальное согласование бренда. Метрики являются снимком на указанное время. Для реальной кампании человек отдельно проверяет речь, кадры, актуальность цены, права на данные и договорные ограничения.
